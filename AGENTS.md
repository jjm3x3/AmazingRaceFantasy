# Agent Instructions

## Committing work

When I ask you to make changes, commit as you go, following these rules:

- Group related patches into the same commit, but keep each commit to as few files as possible.
- If those two goals conflict, prefer fewer files, as long as every commit still leaves the code buildable.
- Commit on the currently checked-out branch.
- Before making any commits, stop and ask me first. List every planned commit with:
  - the patches/files it contains
  - a proposed commit message that starts with a capitalized verb in the imperative mood (e.g. "Add…", "Replace…", "Fix…")
  - a short explanation of what the commit does
- Only commit after I approve the plan.
